# 深度整理（Dream）

像人睡觉时整理记忆：白天只做小步记录，隔一段时间做一次深的归并。目的不是把日志抄进画像，而是让画像长成更准的样子。

## 双环分工

- 前台（每次对话）：新观察写进当天的 `logs/YYYY-MM-DD.md`，小步、准确、不重写画像正文。两种例外可当场动 `profile.md`：用户明确说"记住"的高把握条目，和用户纠错时改正文对应条目（与 `collect-evidence.md` 一致）。
- 后台（Dream）：满足触发条件后，把日志里跨天成立的东西沉淀进画像，把过期的删掉。

触发条件见 `SKILL.md` 的"整理的必然触发"。单次新信号再重要也不触发 Dream——它走前台记日志，等下次 Dream 一起归并。

## 四阶段

按顺序做，不跳步：

### 1. 定向

读 `profile.md` 和 `.last-dream` 之后的所有日志。先分清：哪些是稳定的，哪些是阶段性的，哪些已经过期，哪些互相矛盾。

### 2. 收集

从日志里挑值得沉淀的信号。标准和 `collect-evidence.md` 一致：纠错、确认、反复出现的判断标准、稳定的取舍偏好。一次性情绪、临时任务要求、只出现过一次的弱印象，留在日志里不动。

### 3. 归并

- 跨天重复或被确认的观察 → 提进 `profile.md` 对应分区（把握高进"比较稳"，中进"暂时观察"）。归并时可以按 `form-profile.md` 的"稳不稳"规则升降把握：跨天在真实任务里反复出现的，可升一档再定分区。
- 和画像矛盾的 → 按 `collect-evidence.md` 的矛盾观察规则处理，别单方面覆盖。
- 已被后续行为解除的情绪观察、已确认的"还待确认"条目 → 落定或关闭。"关闭"的意思是：归并时跳过它，并在"最近改动"里记一笔；日志本身不改（日志是归档）。
- 合并进已有条目，不新增重复条目。相对时间改成绝对日期；来源日期已不可考的旧条目不用补。

### 4. 修剪

- 画像正文保持一屏内。"最近改动"最多留 5 条，多了删最旧的。
- 删掉已不成立的条目——直接删，不留"已废弃"标记。
- 已沉淀进画像的日志观察，在日志里可以不管（日志本身就是归档）；但超过一个月的日志如果确认没有未沉淀的信号，可以删。
- 完成后把今天的日期写进 `.last-dream`（一行，如 `2026-07-06`）。只有真正完成四阶段才刷新它，普通前台记录不算。

## 分寸

- Dream 是内部维护，不要变成向用户汇报的仪式。做完最多一句："我把最近的观察归拢了一下。"用户没问就不说。
- 改动要小。Dream 不是重写画像的许可——它和平时一样受"改动要小"约束，只是批量处理。
- 证据不足就跳过。空转一次 Dream（看完没东西可沉淀）是正常结果，照样刷新 `.last-dream`。
- 用户已暂停或删除画像时，不做 Dream。
